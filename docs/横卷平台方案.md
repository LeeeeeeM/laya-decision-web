# 横卷游戏判定演示方案

- 状态：MVP 已落地（引擎 / API / 双游戏前端）；手感与生成仍可迭代
- 内部代号 / API：`platform`（对外中性名；不使用任天堂商标与官方素材）
- 定位：在现有 Laya Decision Web 上新增第二款演示（与 Snake 并列）
- 目标：无限长度横卷游戏判定 + 可选 Laya / mock / Bocha Jev 结构化决策
- 非目标：复刻《超级马里奥》关卡或手感；不使用任天堂名称、角色或像素资源上架宣传

配套数值与碰撞细则见：[横卷平台数值细则.md](./横卷平台数值细则.md)（人物站立/蹲下尺寸、跳高峰高、子弹出生高度与速度、怪/箱尺寸等）。

## 1. 产品说明

极简横版卷轴展示 typed-decision：决策走统一 `DecisionProvider`；物理与生成可测、可复现。

相对 Snake：重力/跳跃更重；**物理 60Hz、决策 4–10Hz（默认 8）**；镜头单向前进。

## 2. 已锁定规则

| # | 议题 | 结论 |
|---|---|---|
| 1 | 镜头与后退 | 镜头只前进。玩家可在画面内往左，左缘卡住，不能走出镜头左侧。 |
| 2 | 怪物 AI | 水平左右巡逻（不追玩家）。侧碰 → 玩家死；踩头 → 怪死并加分 + 小反弹。 |
| 3 | 水坑与跳跃 | 单段虚空为 **1 tile**；相邻虚空之间必须有 ≥1 tile 实地。短跳负责越过单格坑。 |
| 4 | 仿真与决策 | `physics_hz=60` 固定；`decision_hz` 可配 4–10（默认 8）。帧间沿用意图。 |
| 5 | 命名 | 会话 API 使用 `/api/v1/platform/sessions`；UI 文案用「横卷游戏判定」。 |

## 3. 世界与相机

### 3.1 坐标系与尺度（初值）

| 常量 | 初值 | 说明 |
|---|---|---|
| `tile` | 32 px | 逻辑格边长（世界单位与像素 1:1 便于调试） |
| `view_w` | 24 tiles | 镜头宽度 |
| `view_h` | 14 tiles | 镜头高度（含地面上下余量） |
| 地面行 | `y = 2` tiles（脚底） | 实现时可改为连续高度图 |

- X 向右为正，Y **向上**为正（Jump 为正 `vy`）。
- 权威状态存世界坐标；浏览器只做相机变换绘制。

### 3.2 相机

- `camera_x` = 世界左缘，**单调不减**。
- 玩家锚点（建议用脚底中心）超过镜头宽度 **40%** 时，镜头右移以保持锚点在该阈值。
- 玩家 AABB 左缘 ≥ `camera_x`；尝试再左移则水平速度清零并贴边。
- 玩家可接近镜头右缘；生成器保证 `camera_x + view_w` 前方始终有已生成地形。

### 3.3 无限关卡

- Chunk 长度：**16 tiles**。
- 已生成 `[gen_left, gen_right)`；当 `camera_x + view_w + lookahead` 接近 `gen_right` 时追加（`lookahead` 初值 8 tiles）。
- 回收：实体右缘 `< camera_x - 2` tiles 则销毁。
- 地面默认可走；水坑为挖空缺口。

## 4. 实体与规则

### 4.1 玩家

**状态**：`grounded` / `air` / `dead`（行走由速度表达即可）。

**物理初值（验收前可微调，但须满足 §12 黄金用例）**：

| 常量 | 初值 |
|---|---|
| `move_speed` | 6.0 tiles/s |
| `air_control` | 4.5 tiles/s（空中可左右） |
| `gravity` | 40 tiles/s² |
| `jump_v` | 10 tiles/s（短跳） |
| `stomp_bounce_v` | 8 tiles/s |
| Coyote / jump buffer | **MVP 不做** |

**死亡**：落坑、怪侧碰、中弹。无「通关」；无限模式只保留 **本局分数 + 最远 `camera_x` / 距离**。

### 4.2 怪物（巡逻）

| 规则 | 定稿 |
|---|---|
| 水平 AI | **左右巡逻**：出生随机朝左或朝右；前方一步是坑/空洞则掉头 |
| `enemy_speed` | **4.0 tiles/s**（&lt; 玩家 6.0） |
| 同屏上限 | **2** |
| 出生 | 距玩家 ≥ 10 tiles，且在地面、不在坑上 |
| 边缘 | **不走下平台**：前方一步是坑或世界空洞则掉头 |
| 踩头 | 脚部传感器从上落入怪顶，且 `vy <= 0` → 怪死、+100、玩家 `vy = stomp_bounce_v` |
| 侧碰 | 其余 AABB 重叠 → 玩家死 |
| 不追击 | 不朝玩家转向；与玩家 X 无关 |
| Agent 跳跃提示 | 怪物中心距 **1.15–3.40 tiles** 时给出 `need=JUMP`；策略层会确保执行提示动作 |

### 4.3 子弹

| 规则 | 定稿 |
|---|---|
| 运动 | 自镜头右侧外匀速向左，出左缘销毁 |
| `bullet_speed` | 8.0 tiles/s |
| 同屏上限 | **2** |
| 出生距离 | 距玩家水平距离 ≥ max(12 tiles, `bullet_speed * (2 / decision_hz + jump_time_budget)`) |
| 反应时间 | 至少 **2 个决策拍** + 约 0.25s 起跳余量（按当前 `decision_hz` 计算） |
| 命中 | AABB → 玩家死 |

### 4.4 水坑（生成语义定稿）

**硬约束**：

1. 任意单段连续虚空宽度为 **1 tile**，禁止 ≥2。
2. 两段虚空之间必须有 ≥ **1 tile 实地**（禁止「坑贴坑中间无陆地」——那等于更宽虚空）。
3. 「最多两个水坑」指：**同一 chunk 内最多两个 1 格坑段**，中间必须有至少 1 格实地，不是无限贴脸。
4. 短跳水平可达距离必须覆盖 1 tile 虚空（由物理黄金用例保证）；生成器启动时用常量自检。

**删除**：文档旧版「`pit,pit` 中间无地面」模板。

### 4.5 箱子

- 固定悬空高度（箱底约地面上 **2.75** tiles，保证短跳可顶到）。
- 跳跃中头顶碰上箱底（`vy ≥ 0`）→ 首次 **+50** 并 `hit=true`；之后空顶不加分。
- MVP 不顶碎。
- 策略：头顶未顶过的箱子进入起跳窗口时，`need=JUMP`；策略层会确保执行该动作，并在决策事件中标记改写。

### 4.5b 地上道具（钥匙）

- 随机生成在**地面**上的可拾取物（视觉为金色钥匙；逻辑实体名 `item`）。
- **必须蹲下（`CROUCH`）且 AABB 重叠才拾取**；站立走过不会捡起（刻意要求决策出蹲）。
- Agent 在距钥匙中心 ≤ **2 tiles** 时收到 `CROUCH` 提示；若模型动作不匹配，策略层执行提示动作。
- 拾取：`alive=false`，**+40** 分。
- 不造成伤害；同屏建议 ≤ 3。
- 开场为 **seed 随机生成**（仅出生点前有一小段平坦跑道）；无固定 showcase。

### 4.6 计分与进度

| 事件 | 分 |
|---|---|
| 踩死怪物 | +100 |
| 首次顶箱 | +50 |
| 蹲下捡钥匙 | +40 |
| 每向前推进 1 chunk（`camera_x` 跨过） | +10 |

展示：`score`、`distance_tiles = floor(camera_x)`、本局最佳由前端或服务端 reset 时可选保留（MVP 可不做全局持久化）。

### 4.7 同屏实体上限汇总

| 类型 | 上限 |
|---|---|
| 敌 | 2（实现侧） |
| 弹 | 2（实现侧） |
| 地上道具 | ≤ 3 |
| 可见箱 | 按生成自然出现，建议同屏 ≤ 2 |
| 坑段 | 视野内不限，但受 chunk 规则约束 |

## 5. 随机生成（chunk 表）

Chunk = 16 tiles。加权模板（示例权重，实现可配置）：

| 模板 | 内容 | 权重 |
|---|---|---|
| empty | 全实地 | 30 |
| pit1 | 一个 1 格坑（两侧留跑动边距） | 18 |
| twin_pit1 | 两个 1 格坑，中间 ≥1 格岛，两侧边距充足 | 8 |
| enemy | 平坦 + 远端怪 | 12 |
| bullet | 平坦 + 计划发球（满足反应时间） | 10 |
| box | 平坦 + 1 箱 | 8 |
| item | 平坦 + 地面钥匙（需蹲捡） | 12 |

**可解性硬规则**：

1. 虚空宽度 ≤ 2，且坑间有实地。
2. 怪/弹满足出生距离与反应时间。
3. 任意滑动窗口 5 个 chunk 内至少 1 个 `empty`。
4. 用固定 `seed` 的确定性 RNG，保证同 seed 序列一致。

## 6. 物理循环

- 固定 `dt = 1/60`；不因渲染掉帧而改变权威步长（可追帧，设每渲染帧最多追 N 步防螺旋）。
- 顺序：读意图 → 水平/动作 → 积分 → 地形碰撞 → 实体碰撞 → 相机 → 生成/回收 → 死亡判定。
- **空中**可左右（`air_control`）；**无二段跳**。

### 6.1 黄金用例（必须单测）

1. 站立短跳过 1 格坑 → 成功。  
2. 不跳直接进入坑 → 死亡。
3. 蹲下经过子弹 → 不被命中。
4. 蹲下与钥匙重叠 → 成功拾取并加分。

## 7. 动作与决策

### 7.1 意图通道（定稿）

两路意图，决策拍更新，物理帧消费：

- `move` ∈ {`LEFT`,`RIGHT`,`IDLE`}
- `action` ∈ {`NONE`,`JUMP`,`CROUCH`}

| 组合行为 | |
|---|---|
| `JUMP` 且 grounded | 立即短跳 |
| `CROUCH` 且 grounded | 进入蹲姿，允许慢速移动、躲避子弹或拾取钥匙 |
| 空中 `JUMP`/`CROUCH` | 忽略 |

### 7.2 频率与命名

| 参数 | 含义 | 默认 |
|---|---|---|
| `physics_hz` | 物理 | 60（不可配乱改） |
| `decision_hz` | 决策 | 8（范围 4–10） |

**不要**再复用 Snake 的 `fps` 表示物理步进；平台会话字段使用 `decision_hz`。若 UI 共用控件，需标签写清。

- Provider 超时：保持上一意图，可 `cooldown`/`error`（对齐 Snake）。
- **Bocha Jev**：默认 `decision_hz=1`（上限 2），避免 QPS/费用爆炸；Laya/mock 可用 8。

### 7.3 Prompt 与 L96 预算

- 只描述：**前方 `K=12` tiles** 内最近威胁，最多 **3** 个对象 + 脚下状态。
- 禁止把整屏实体列表塞进 state。

State 模板（控制体量；`need=` 置首，避免 L96 截断丢动作线索）：

```text
need={NONE|JUMP|CROUCH} ground={0|1} {pit1|enemy|bullet|box|item}@{rel} ... x={dx}
```

`dx` 用相对镜头或相对玩家的小整数，避免大坐标浪费 token。

问题（必须极短，否则 prefix 吃光 96，**state 进不去 → choice 概率恒定**）：

- `move` choice：RIGHT/LEFT 全选项；`go=` 匹配项 criteria=`Best. Matches go=…`，其余 `Worse.`（cue 项优先）
- `action` choice：NONE/JUMP/CROUCH 全选项；`need=` 匹配项同样 Best/Worse

组装后必须在 Laya ANE **max_length=96** 内；CI 或单测对样本 prompt 做 token 长度断言（见 `TestPlatformQuestionTokenBudget`）。

### 7.4 安全层

横卷平台的 `move` 仍按模型输出执行；当 `need=JUMP` 或 `need=CROUCH` 时，策略层确保执行提示动作。若动作被改写，决策事件会保留模型建议的 `proposed`、实际执行的 `executed`，并将 `intervened` 置为 true。`need=NONE` 时动作按模型输出执行。

## 8. 架构与权威模型

```text
Browser Canvas (platform view)
    ↕ HTTP + SSE
Go platform session
    ├─ platform.Game     物理权威（决策模式必开）
    └─ platform.Policy   组题 → Provider → 意图
```

### 8.1 人控 vs 决策（定稿，避免 60Hz HTTP）

| 模式 | 权威 | 输入 |
|---|---|---|
| **human**（MVP 阶段 2–3） | **浏览器本地物理**（Go 可只提供 seed/静态配置，或不上权威） | 键盘本地，零 RTT |
| **agent**（mock/laya/jev） | **Go 权威 60Hz** | 仅决策意图 4–10Hz；浏览器只渲染 SSE |

人控若坚持 Go 权威：输入采样 ≤ **30Hz**，合并按键状态，禁止每物理帧 POST。

推荐产品路径：**人控本地 → 验证手感 → agent 模式切 Go 权威**（两套共享同一物理常量与生成器代码：Go 实现为源，人控可用 WASM/TS 移植或仅 agent 演示——MVP 允许先 **人控也 Go 权威但 30Hz 输入**，以减少双实现；若手感差再改本地物理）。

**MVP 折中（推荐写进实现）**：始终 Go 权威；人控 `POST/controls` 发送按键位图，频率 **20–30Hz**；物理 60Hz 在服务端插值/保持。本机 RTT 足够。

## 9. API（建议）

```
POST   /api/v1/platform/sessions
GET    /api/v1/platform/sessions/{id}/events
POST   /api/v1/platform/sessions/{id}/controls
DELETE /api/v1/platform/sessions/{id}
```

创建字段：`provider`, `decision_hz`, `seed`, `mode`=`human|agent`。

SSE：`snapshot` / `decision` / `status`（字段含 `camera_x`, `player`, `entities`, `score`, `distance`, `move`, `action`, …）。

## 10. 前端 MVP

- Canvas 色块实体 + 动作状态。
- 侧栏：score、distance、意图、概率、延迟、intervened、decision_hz。
- 与 Snake 分页面或 Tab，避免一套控件混用 `fps` 语义。

## 11. 实施阶段

1. 常量表落地 + 生成器可解性单测。  
2. Go 引擎人控（30Hz 输入）+ 黄金用例。  
3. SSE + Canvas。  
4. Policy + mock @ 8Hz + 动作意图验证。
5. Laya（L96 断言）/ Jev（1Hz）。  
6. 手感打磨。

## 12. 验收标准

1. 镜头永不左移；左缘卡住。  
2. 黄金用例 1–4 全过。  
3. 踩头/侧碰正确；左 20% 停追；敌速 &lt; 玩家速。  
4. 子弹反应时间公式满足；同屏敌/弹 ≤2。
5. 生成 1000 chunk：无 ≥2 虚空、无坑贴坑无陆地、窗口内有 empty。
6. `decision_hz=8` 时物理仍 60Hz；决策间沿用上一动作意图。
7. 同 seed 序列一致。  
8. 样本 prompt token ≤ 96（Laya）。
