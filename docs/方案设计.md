# Laya Decision Web 方案设计

- 状态：首版已落地（Go API / SSE / Snake / mock·Jev·Laya ANE / Vite Canvas）
- 前端：Vite + TypeScript
- 服务端：Go
- 本地模型：Go + macOS Core ML 原生桥接；运行时不要求 Python
- 线上模型：Bocha Jev HTTP API

## 1. 项目目标

在本机启动浏览器应用，通过同一套决策接口切换 Laya 本地模型和 Bocha Jev 线上 API，并用 Snake 演示候选动作概率、延迟和安全层行为。

两种 provider 返回统一的结构化结果，覆盖 choice、score、noul。Bocha Jev 是结构化决策 API，不作为自由文本生成或聊天接口使用。

## 2. 首版范围

- 本机单用户服务，默认只绑定 127.0.0.1。
- 浏览器创建、暂停、恢复、重开 Snake 会话并调整目标速度。
- Go 服务端维护游戏状态、运行安全层并串行调用决策 provider。
- 通用决策接口可独立于 Snake 使用。
- Jev 密钥只由服务端读取，不发给浏览器。
- 建立与当前 Python 项目的模型输入、概率输出、游戏动作和安全层 parity 测试。
- 前端使用 Canvas 显示游戏板、方向概率、模型建议动作、实际执行动作、推理延迟和 provider 状态。

首版不包含公网多租户、账户和计费、任意模型代码上传、浏览器直连 Bocha 或自由文本 LLM 生成。

## 4. Go 服务模块

建议使用标准库 net/http 开始，避免首版引入较多运行依赖。

- cmd/server：加载配置、初始化 provider、启动服务。
- internal/config：环境变量、模型缓存、启动校验。
- internal/decision：共享请求/回答类型和 provider 接口。
- internal/decision/jev：Jev HTTP 客户端、超时、响应校验、Retry-After。
- internal/decision/laya：tokenizer、问题模板、batch/tensor 组装、概率后处理、模型管理。
- internal/coreml：cgo 声明和 Objective-C 实现，负责加载模型和执行 Core ML prediction。
- internal/snake：游戏规则、状态、路径规划和安全层。
- internal/session：游戏循环、provider 调用串行化、SSE 广播。
- internal/httpapi：路由、输入校验、错误映射和 CORS。
- frontend：Vite + 原生 TypeScript、Canvas 与 CSS。

概念上的 provider 接口：

~~~go
type DecisionProvider interface {
    Name() string
    Decide(ctx context.Context, request DecisionRequest) (DecisionResponse, error)
}
~~~

Provider 只负责决策，不推进游戏。会话控制器收到合法答案后，先运行安全层，再应用动作。

## 5. Laya 本地推理

### 5.1 Core ML 原生桥

Core ML 是 Apple 原生框架。Go 没有内置 Core ML 包，但 cgo 可以调用 Objective-C，Go 工具链支持构建 .m 文件。因此可由 Objective-C 桥调用 Core ML，Go 继续负责 Web 服务和 Laya 决策逻辑；Python 不是必需的运行时依赖。

桥接职责保持窄小：

1. 输入模型目录、Compute Units 和连续数值张量。
2. Objective-C 创建 MLModel、MLFeatureProvider / MLMultiArray，并运行 prediction。
3. 返回输出张量或可诊断错误给 Go。

本地模型需要 macOS、Xcode Command Line Tools 和兼容 Apple Silicon。非 Apple 平台可继续构建 Jev provider，但报告本地 Core ML 不可用。

参考：[Go 对 Objective-C .m 文件的支持](https://go.dev/cmd/go/#hdr-File_types)、[Apple Core ML 模型加载 API](https://developer.apple.com/documentation/coreml/mlmodel/load%28contentsof%3Aconfiguration%3Acompletionhandler%3A%29)。

### 5.2 需要移植的 Laya 逻辑

Core ML 桥只运行模型图，不会自动完成 Laya typed-decision 流程。Go 侧需要实现并验证：

1. 读取 tokenizer.json 和特殊 token 配置。
2. 依照 choice、score、noul 构造序列、选项 markers 与长度截断。
3. 生成模型输入张量、batch padding 和形状。
4. 解读 logits，执行 temperature 校准和 softmax。
5. 还原标签、概率、score、confidence 和 usage。
6. 校验模型 manifest、输入形状和输出有限性。

语义与 typed-decision 流程以本仓库 `internal/decision/laya` 为准（prompt 组装、tokenizer、logits 后处理）。

### 5.3 模型类型和 ANE

当前仓库包含常规 Core ML 模型和 ANE 专用包。常规模型主要向 Core ML 提交整理后的输入张量。ANE 专用路径还需在宿主侧完成 embedding lookup、attention mask、action head 与 safetensors 读取（见 `internal/decision/laya`）。

建议按阶段支持：

- MVP：支持常规 CPU/GPU Core ML 模型，先验证完整 Go 原生输入、模型运行和概率后处理路径。
- ANE 阶段：把 ANE host-side 运算及 safetensors 读取移植到 Go，再开启 CPU + Neural Engine；通过与 Python ANEAgent 的 golden parity 后才标记可用。
- 如果首版必须使用当前 ANE 专用包，就把 ANE 阶段纳入首版验收，不能只以模型文件加载成功作为完成标准。

### 5.4 模型管理

- 服务端配置允许使用的本地路径或 Hugging Face repo ID 与 revision。
- 模型下载到 LAYA_MODEL_CACHE_DIR，记录固定 revision、实际提交 SHA 和 manifest 校验。
- 需要私有模型时由 HF_TOKEN 提供凭据；公开模型不要求 token 时无需配置。
- 下载、校验、Core ML 编译、模型加载是独立状态，前端显示状态和错误。
- 下载的 Hub 快照可能包含 symlink。进入 Core ML 编译缓存前要物化文件并校验 SHA。
- 浏览器只选择服务端登记的模型 ID，不接收任意文件系统路径。

## 6. Bocha Jev provider

- endpoint：POST https://jev.bocha.cn/v1/systemone
- 默认模型：bocha-jev-v1
- 密钥：BOCHA_JEV_API_KEY；兼容 BOCHA_SEARCH_API_KEY。
- 每一步将 Snake 的多个问题合并为一次请求。
- Go 负责超时、请求体校验、响应类型校验、日志脱敏和限流。
- 对 429 / 503 / 529 读取 Retry-After 并有限退避；等待过久时暂停会话并显示冷却时间。
- 同一游戏会话最多一个在途决策请求。账号默认限额不是吞吐保证，实际值以账户配置为准。
- 不发送 stream 或 conversation history 等 Jev 不支持的字段。

## 7. Snake 和浏览器

Go 维护权威游戏状态，浏览器负责渲染和控制。状态包括 board、seed、snake body、food、score、tick、alive/won、provider 信息、当前决策和会话状态。

前端控制包括 provider / 本地模型选择、速度、开始、暂停、恢复、重开。Canvas 显示蛇盘；侧栏显示方向概率、建议与实际动作、安全层介入、风险估计、推理耗时和在线/离线状态。

单步时序：

1. 会话步频定时器触发。
2. Go 用当前 state 调用 provider。
3. 服务端校验答案和方向概率。
4. 安全层过滤动作并更新游戏。
5. 服务端生成快照并通过 SSE 推送。

若请求超时或限流，不应用旧答案、不推进游戏；会话进入可见的 cooldown/error 状态。

### 速度和限流

- 本地 Laya 目标速度默认可设 12 steps/s。
- Jev 默认 1 step/s，允许账号额度支持时设置到 2 steps/s 试运行。
- FPS 是目标值，不是保证值。请求响应时间、限流等待和全局 limiter 都会降低实际速度。
- 2 fps 约为每局每秒两次 API 请求；多局并发时请求量相加，须由全局限流器控制。

## 8. 配置和安全

- 默认监听 127.0.0.1；CORS 只允许 Go 页面和配置的本地 Vite 开发源。
- API key / HF token 仅在 Go 服务端环境或 gitignored 的权限受限配置文件中读取。
- 密钥不进 TypeScript、浏览器 localStorage、源码、日志、错误栈或响应。
- .env.local、模型权重、Core ML 编译缓存、录制文件和临时下载加入 .gitignore。
- 校验 state、questions、请求体大小、board 尺寸、fps、候选项、model ID 和 token budget。
- 禁止浏览器输入任意 URL，防止服务成为开放代理。
- 公网部署需另行设计身份认证、配额、CORS 和密钥轮换，不在本机首版范围。

建议配置：

| 变量 | 用途 |
|---|---|
| LISTEN_ADDR | 默认 127.0.0.1:18080 |
| BOCHA_JEV_API_KEY | Bocha Jev API Key |
| BOCHA_JEV_TIMEOUT | 远端调用超时 |
| BOCHA_JEV_MAX_QPS | 服务端 Jev 全局 QPS 限制 |
| BOCHA_JEV_MAX_FPS | Jev Snake 目标步频上限 |
| LAYA_MODEL_CACHE_DIR | 模型下载和编译缓存 |
| LAYA_MODEL_ID / LAYA_MODEL_DIR | 默认模型 repo ID 或本地目录 |
| LAYA_MODEL_REVISION | 固定模型 revision |
| LAYA_LOG_IO | 调试时记录 Laya 输入、tokenized input 和 typed output，默认关闭 |
| HF_TOKEN | 私有模型下载凭据，可选 |

## 9. 验收与测试

1. Core ML bridge：加载登记模型，验证输入输出名称、shape、dtype 和 compute units。
2. Tokenizer parity：逐字对比 Go/Python token IDs、markers、截断和 batch 输入。
3. Decision parity：用固定输入比较 logits 和概率，基于实测确定数值容差。
4. ANE parity：覆盖 host embedding、mask、action head 和 safetensors 权重。
5. Jev mock：测试成功、401、超时、429 Retry-After、无效 JSON 和多问题单请求。
6. Snake parity：固定 seed 比较状态演进、碰撞、吃食、重开和安全层动作。
7. Browser：验证 SSE 重连、暂停/恢复、限流状态、错误反馈和无重叠请求。
8. Secret scan：确认源代码、git diff 和前端构建产物不含 key/token。
